# Independent Closure Audit — architecture first

ICA is mandatory before accepting M-CONVERSION or a selected product milestone complete. It is a
fresh isolated audit context or independent human/auditor, not the coding role, strategic role's
second pass or bootstrap generator's self-review. Record actual auditor/context/model/entry point,
prior involvement and isolation evidence. A validator can check declarations; it cannot establish
true independence or correctness. Existing WO0010 review remains historical evidence, not retroactive ICA.

Input order: attributable human target scope; full current ARCHITECTURE.md and its exact digest;
canonical requirement map; exact current merged product/governance revision; then enforcing source,
runtime entry points, tests and negative evidence. Do not start with strategy's claim of completion.
Use IMPLEMENTED, PARTIAL, ABSENT, UNPROVEN for every applicable requirement. Initially matrix rows
are UNPROVEN until the auditor substantiates them. Explicitly deferred functionality is recorded as
out-of-target with its authority, not silently omitted or called implemented.

Each row names SAR ID, scope/deferral, enforcing path/actual boundary, actual test/command/evidence,
negative paths, result, limits, audited revision, confidence and required remediation. Read full
architecture, not only planned tasks. Mocked authority/routing/persistence/deployment cannot prove
those boundaries. A passed helper test cannot establish product/real-client/runtime acceptance.

Outcome includes blockers and narrow H/A/E/I/C-linked repair suggestions. After remediation, rerun
the architecture-to-current-main matrix, not just closed finding IDs. Changed relevant source/head
requires freshness assessment. Audit output is read-only by default: no implementation, merge,
CRITICAL disposition or release approval. Human decides applicable judgments/target readiness and
separately release/exposure/deployment. Independent audit never substitutes for that decision.

Materialize templates/request drafts and a complete initial matrix from specifications/REQUIREMENTS.json.
M-CONVERSION includes preservation and role/protocol/authority constraints; M-LOCAL-PILOT-EVIDENCE
includes all applicable product boundaries. Do not invent accepted targets, measured results,
independent identities or future revisions in inactive audit drafts.
